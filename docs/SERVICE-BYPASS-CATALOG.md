# Каталог исключений российских сервисов

Версия `2026-10-06.1`, экспериментальная. Источник для приложения и расширения — `Shared/Resources/ServiceBypassCatalog.json`.

6 октября 2026 года проверены DNS A/AAAA указанных в ресурсе доменов через публичный resolver Cloudflare и соответствующие записи RIPE RDAP (`https://rdap.db.ripe.net/ip/<address>`) и RIPEstat network-info (`https://stat.ripe.net/data/network-info/data.json?resource=<address>`). DNS наблюдался с Mac, не с iPhone и не обязательно из той же сети, которой будет пользоваться тестер. Это основания для начального каталога, а не доказательство полного покрытия приложения.

Для каждой записи сохранены CIDR, имя регистрации, ссылка на первичный источник и домены, адреса которых попали в диапазон. Выбирается более узкий из содержащих адрес зарегистрированного диапазона и наблюдаемого BGP-префикса. Принадлежность сети не гарантирует отсутствие сторонних арендаторов; общий IP влияет на все приложения, поэтому режим требует явного включения.

| Группа | Записей в ресурсе | Основание |
|---|---:|---|
| Ozon | 3 | `OZONRU-DCZ1-NET2/3/4`, сети /24 для сайта, API и изображений |
| Wildberries | 10 | Зарегистрированные/анонсируемые диапазоны Wildberries для сайта, API, static-basket и basket; один IPv6 host snapshot |
| Яндекс | 15 | Отдельные зарегистрированные /24, IPv6 /48 и /62 для Поиска, ID, карт, Go, Почты, Диска и статических ресурсов |

После удаления вложенных записей итоговый набор меньше исходного. Не добавлены все сети России, ASN целиком, Yandex Cloud целиком, публичный DNS Яндекса `77.88.8.8` или весь IPv6-префикс WB.

**Временная запись Wildberries:** `2a03:720::173:2/128` — только наблюдаемый адрес сайта. Реестр даёт слишком широкий `/32`, поэтому он не включён. Host snapshot может устареть; эта запись не считается устойчивым покрытием IPv6 приложения. Обновлять по результатам испытаний, не расширяя автоматически до `/32`.

**Пробелы:** сценарии авторизации, корзины, региональных CDN и нативного Go пока не проверены. `user-auth.wildberries.ru` и `www.wbstatic.net` в исследовании не дали A/AAAA; правил для них не добавлено. Для поиска недостающих зависимостей нужны реальные сценарии из `docs/DEVICE-TESTING.md`. Списки доменов в ресурсе описывают наблюдения и не используются как wildcard-правила.

## Обновление

1. Воспроизвести конкретный сбой на iPhone; отдельно доказать, что проблема в маршруте, а не в самом сервисе или распознавании активного VPN.
2. Найти фактические назначения проблемного соединения без TLS MITM и записи пользовательского содержимого.
3. Сопоставить A/AAAA с действующим каталогом. Проверить DNS через VPN: он может выбрать другой CDN, чем обычная сеть.
4. Проверить отсутствующий адрес в RIPE RDAP и RIPEstat. Общая сеть хостинга или чужой CDN не получают исключение целиком. В спорном случае оставить маршрут через VPN и зафиксировать ограничение.
5. Обновить ресурс, `catalogVersion`, `reviewedAt`, источники и эту записку. Не удалять запись только из-за одного временного DNS-отказа.
6. Выполнить `make test`, `make strings-check`, `make release-check`; проверить три группы отдельно и вместе на устройстве.

Клиент не загружает этот список из сети и не обновляет его фоновым процессом. Изменения доставляются новой сборкой. Поле `reviewedAt` — дата исследования, а не обещание срока действия адресов.
