# Российские сервисы при включённом VPN

Дата: 6 октября 2026 года. База: `647cd2e` (`main`, сборка 0.1.0 (3)).

Цель: пользователь в России оставляет OVoC Client подключённым и пользуется Ozon, Wildberries и сервисами Яндекса, включая Яндекс Go. Для выбранных сервисов используется обычное подключение телефона; остальной трафик сохраняет текущую политику VPN.

Статус на 6 октября 2026: после ревью пользователь поручил реализацию, затем явно выбрал подготовку кода и сборки с проверкой iPhone позже. Подготовлена экспериментальная реализация 0.1.0 (4): модель, каталог, маршрутизация, сохранение профиля, интерфейс и тесты. Это согласованный перенос проверки этапа 1: пригодность каталога и поведение маршрутов на iPhone ещё не подтверждены. Выпуск для широкой раздачи остаётся за этой проверкой. Наличие штатного API исключений само по себе не доказывает, что приложения перестанут выдавать предупреждение о VPN.

Решения экспериментальной сборки: `enforceRoutes` сохраняет прежнее значение (новое поведение не включено без устройства); `includeAllNetworks` выключен. Каталог содержит узкие сети из RDAP/BGP и один явно обозначенный временный IPv6 host snapshot WB — полный `/32` не добавлен. Подробности и пробелы: [SERVICE-BYPASS-CATALOG.md](SERVICE-BYPASS-CATALOG.md). В локальном ключе найдены одна директива route и один net_gateway; отдельный механизм MAX не подтверждён, установленный профиль и правила сервера требуют проверки позже.

## 1. Что уже есть

| `PacketTunnel/Runtime/TunnelNetworkSettingsUpdate.swift` | Игнорирует промежуточный `nil` при reconnect, сохраняя маршруты и DNS | Сохраняем это поведение и проверяем его вместе с исключениями |

| `Package.swift`, `Tests/` | Тесты сетевых настроек, IPv6 и общего кода запускаются на Mac | Расширяем текущие тестовые точки |

**MAX.** Пользователь указал, что похожее поведение есть в установленном OVoC Client. Поиск по исходникам, локальной истории и доступным веткам GitHub отдельного механизма MAX не обнаружил; удалённый `main` совпадает с базой плана. Это не проверка установленного профиля: маршруты могли прийти из ключа или от сервера, а работа MAX сама по себе не доказывает наличие исключения. На этапе 0 устанавливаем источник поведения. Найденные действующие исключения сохраняем; MAX включаем в регрессионную проверку, но новые сети MAX без подтверждения не добавляем.

## 2. Пользовательское поведение

Добавить экран **«Без VPN»** с пояснением **«Российские сервисы»** и тремя переключателями:

- **Ozon** — сайт и приложение, включая изображения, авторизацию и API.
- **Wildberries** — сайт и приложение с теми же базовыми сценариями.
- **Яндекс, включая Go** — общая группа, поскольку Go, Яндекс ID, карты и другие сервисы используют общую инфраструктуру.

Проверяемый минимум группы Яндекса: Поиск, Яндекс ID, Карты, Почта, Диск и Go. Другие сервисы на подтверждённых общих сетях тоже могут работать напрямую, но формулировка «весь Яндекс гарантированно работает» до проверки неприемлема. Сторонние сайты в Яндекс Браузере не становятся исключениями из-за того, в каком браузере они открыты.

Решения первой версии:

1. Все новые исключения **выключены по умолчанию**, в том числе после обновления существующей установки. Пользователь включает нужные группы; есть действие «Включить все».
2. Не определяем Россию по IP, SIM или языку системы. Режим доступен всем; за рубежом он использует местное подключение, а не создаёт российский IP.
3. Под переключателями короткий текст: «Выбранные сервисы работают напрямую, с IP вашей сети. Выбор сохраняется автоматически». Подробности об общих IP и экспериментальном статусе — в свёрнутом блоке «Подробнее».
4. Изменять и сохранять настройку можно только при отключённом VPN. При активном соединении показываем применённый выбор и текст «Чтобы изменить исключения, отключите VPN». Отключение — явное действие пользователя; после сохранения он подключается обычной кнопкой.
5. Не сохраняем скрытые изменения «на потом», не перезапускаем VPN автоматически и не делаем вид, что новый выбор уже применился.
6. Сборка 7 исправляет обнаруженную пользователем потерю временного выбора при закрытии экрана в сборке 4. Каждый переключатель и кнопка «Включить все»/«Выключить все» сразу записывают выбор. До завершения сохранения и перечитывания закрытие и повторное редактирование блокируются; при ошибке показаны фактический выбор и сообщение. «Готово» и свайп не отбрасывают несохранённый черновик.
7. На главном экране при включённых исключениях показываем краткую строку «Без VPN: Ozon, Яндекс» с переходом к настройке. При выключенных исключениях строку не показываем; вход в экран остаётся доступным.
8. ru/en, VoiceOver и Dynamic Type входят в объём. До импорта первого ключа объясняем, что настройка станет доступна после добавления ключа; второй источник хранения предпочтений не заводим.

Это продуктовые решения плана, а не уже подтверждённые предпочтения пользователя. Их можно изменить до реализации интерфейса.

## 3. Архитектура

**Выбранный первый вариант: встроенный, проверяемый каталог IP-сетей сервисов и штатные `excludedRoutes` iOS.** Он не требует своего прокси, сервиса обновлений или смены OpenVPN/Cloak.

```text
Экран «Без VPN»
    → TunnelManager: проверка состояния → save → load
    → providerConfiguration: версия политики + ID выбранных сервисов
    → PacketTunnelProvider: снимок политики на время сессии
    → встроенный каталог → валидация → объединение маршрутов
    → NEPacketTunnelNetworkSettings → setTunnelNetworkSettings

Трафик к выбранным IP → обычная сеть телефона
Остальной трафик       → прежняя маршрутизация OpenVPN/Cloak
Системный DNS         → прежние DNS-серверы через VPN
```

У Apple есть исключения для IPv4 и IPv6. Правило применяется к адресу назначения, независимо от того, какое приложение открыло соединение. Per-app VPN для управляемых приложений требует MDM и не подходит для обычной установки нашего клиента через TestFlight. См. [маршрутизацию VPN](https://developer.apple.com/documentation/networkextension/routing-your-vpn-network-traffic), [IPv4 excludedRoutes](https://developer.apple.com/documentation/networkextension/neipv4settings/excludedroutes), [IPv6 excludedRoutes](https://developer.apple.com/documentation/networkextension/neipv6settings/excludedroutes), [NETunnelProviderManager](https://developer.apple.com/documentation/networkextension/netunnelprovidermanager). Семантика маршрутов дополнительно сверена с заголовками локального iPhoneOS 26.2 SDK.

Домены нужны для исследования покрытия, но не являются маршрутами. Однократное разрешение трёх главных доменов недостаточно: оно пропускает зависимости и смену адресов. Аналогичное ограничение описано в [документации Amnezia](https://docs.amnezia.org/documentation/instructions/vpn-split-tunneling/). Её реализацию не считаем готовой частью нашего клиента.

### 3.1. Каталог адресов

Каталог содержит `schemaVersion`, `catalogVersion`, `reviewedAt`, стабильные ID `ozon`, `wildberries`, `yandex`, списки IPv4/IPv6 CIDR. Для каждой сети в сопровождающем реестре указываем источник, дату проверки, назначение и основание включения. Конкретный полный список адресов пока **не установлен** — это результат этапа 1, а не предположение плана.

Правила наполнения:

- Начальные точки исследования: `ozon.ru`, `wildberries.ru`, `yandex.ru`, `ya.ru`, `go.yandex.ru`. Это примеры доменов, а не готовый allowlist. По реальным сценариям дополняем API, авторизацию, редиректы, карты, изображения и загрузки.
- Проверяем публичные сведения владельцев и распределения сетей, актуальные DNS-ответы и фактические назначения соединений с тестового iPhone в российской сети. ASN и сторонний список — подсказка для исследования, не автоматическое разрешение всей сети.
- Не исключаем `.ru`, все российские IP, весь ASN хостинга, Yandex Cloud целиком или общие CDN целиком. Даже собственная сеть компании может обслуживать сторонние ресурсы: принадлежность сети сама по себе не доказывает узкое покрытие.
- Общий IP невозможно разделить по доменам этим механизмом. Для каждого такого случая оцениваем побочный охват. Если без широкого исключения обязательный сценарий не работает, это основание пересмотреть архитектуру, а не незаметно расширить список.
- Не выдаём временный DNS-снимок `/32` или `/128` за устойчивый каталог. Если для обязательной зависимости нет подходящего поддерживаемого диапазона, фиксируем пробел и проверяем следующий вариант архитектуры.
- Проверяем объединения и пересечения групп. Отключение группы не убирает адрес, нужный другой включённой группе; существенно пересекающиеся сервисы объединяем или объясняем пересечение в интерфейсе.
- Обновление каталога в v1 — через новую сборку с ревью diff и повторной проверкой сценариев. Перед каждым выпуском перепроверяем покрытие. Если адреса меняются слишком часто, встроенный каталог не проходит критерий пригодности.

Ресурс хранится в репозитории один раз, например `Shared/Resources/ServiceBypassCatalog.json`, и включается в оба bundle. Код получает bundle/resource URL явно; SwiftPM-тесты используют свой ресурс, а не неявный `Bundle.main`. `project.yml` и ресурсы `SharedRuntime` обновляются вместе. Клиент во время старта не скачивает списки и не ждёт дополнительных DNS-запросов.

### 3.2. Хранение и совместимость

- Новое поле `serviceBypassPolicy` в `providerConfiguration`: версия схемы и массив стабильных ID. Типы — совместимые с property list. Модель и валидатор находятся в `Shared`.
- Единственный источник сохранённого выбора — профиль iOS. В UserDefaults не дублируем.
- Отсутствие поля в старом профиле означает пустой выбор и прежнее поведение.
- Неизвестная версия, неверный тип или неизвестный ID в непустой политике дают понятную ошибку, а не молчаливое изменение маршрутизации. Пустой выбор не должен зависеть от пригодности каталога.
- Смена ключа сохраняет выбранные группы; новый профиль без предыдущего выбора получает пустой список. Неудачный импорт не меняет выбор или существующий ключ.
- Изменение только исключений сохраняет сертификаты, `ovpnConfig`, DNS, endpoint и прочие поля профиля. Это отдельная операция, а не повторный импорт ключа.
- Сохранение считается успешным после `saveToPreferences` и `loadFromPreferences`. При сбое показываем ошибку и перечитываем фактическую конфигурацию. При неудачном чтении не изображаем известный применённый выбор и не запускаем туннель из устаревшего объекта.
- Блокировка операций общая для сохранения, импорта и подключения. Повторная проверка `connection.status` перед записью обязательна: `@MainActor` сам по себе не исключает чередование операций после `await`.

### 3.3. Сборка маршрутов

Выделить чистую тестируемую политику в `Shared` и преобразование в типы NetworkExtension в `PacketTunnel/Runtime`. В `PacketTunnelProvider` оставить чтение конфигурации и вызов этой политики на существующей `stateQueue`.

Порядок применения:

1. Получить настройки адаптера и действующие DNS так же, как сейчас.
2. Проверить выбранные группы и каталог. Нормализовать CIDR, убрать дубликаты, объединять только диапазоны, объединение которых не добавляет ни одного нового адреса.
3. Сохранить все исходные `includedRoutes` и `excludedRoutes` адаптера, включая потенциальные исключения MAX. Сохранить обязательное исключение Cloak-сервера. Новая функция управляет только своими добавками.
4. Проверить конфликты новых исключений с адресами DNS и служебной адресацией туннеля. В v1 при таком конфликте отказываем в запуске с конкретным сообщением: «Исключения конфликтуют с DNS вашего VPN. Отключите исключения или измените DNS в профиле». Не выводим весь DNS наружу и не выкидываем молча часть списка. Отдельный тест — публичный DNS внутри сети Яндекса.
5. Добавить IPv4 CIDR в `ipv4Settings.excludedRoutes`; вернуть объект обратно в свойство с семантикой `copy`.
6. Если сервер не дал IPv6, создать прежнюю IPv6-раковину. Затем добавить **только подтверждённые** IPv6 CIDR сервисов в `ipv6Settings.excludedRoutes`. Если сервер дал IPv6, сохранить его настройки и добавить исключения к ним.
7. Сохранить `matchDomains = [""]`, fallback DNS, MTU и фильтр IPv6. Прямой IPv6-трафик из исключений не должен попадать в `packetFlow`; весь остальной IPv6 остаётся под прежней политикой.
8. Одним вызовом применить полный объект настроек; успех сообщать только после completion iOS. При каждом новом наборе настроек адаптера пересобирать результат из его исходных маршрутов и снимка политики, без накопления старых добавок.
9. При `nil` от адаптера оставить установленный объект в силе, как делает текущий `TunnelNetworkSettingsUpdate`. Не вызывать `setTunnelNetworkSettings(nil)` ради обновления исключений.

Для режима исключений явно использовать `includeAllNetworks = false`. В прототипе проверить `enforceRoutes = true`: Apple описывает его как способ закрепить included/excluded routes за VPN и основной сетью при выключенном `includeAllNetworks`. Это изменение может повлиять на транспорт Cloak и локальную сеть, поэтому не включаем его вслепую для всех профилей. Окончательное значение для режима исключений фиксируем по результатам этапа 1; режим с пустым выбором сохраняет прежнее поведение. См. [enforceRoutes](https://developer.apple.com/documentation/networkextension/nevpnprotocol/enforceroutes).

Ни сохранение маршрутов при reconnect, ни `enforceRoutes` не являются обещанием нового kill switch. При полном выключении/падении VPN действует существующее системное поведение. Не меняем его незаметно в рамках этой функции.

### 3.4. Проверка данных и ограничения

- Разбирать адреса библиотечным парсером, проверять длину префикса, нормализованную сетевую часть и семью адреса. Не допускать default route, loopback, unspecified, multicast, link-local, private/ULA и других специальных диапазонов в новом каталоге сервисов.
- Запреты каталога не применяются задним числом к исходным маршрутам ключа или адаптера: это отдельная существующая политика, которую нужно сохранить.
- Проектные лимиты реализации: ресурс до 256 КиБ, до 1024 исходных записей суммарно, включая обе семьи; нормализация дополнительно сокращает число установленных маршрутов. Это наши ограничения для прототипа, а не документированные лимиты iOS. Превышение — явная ошибка; список не обрезаем.
- По умолчанию в логах только версия каталога, выбранные ID, число маршрутов и код ошибки. Не пишем посещённые домены, URL, аккаунты, содержимое пакетов и полные DNS-ответы.
- Нет сетевых запросов ради каталога на старте, таймера опроса и дополнительной работы на каждый пакет. Измеряем время установки маршрутов и память расширения относительно текущей версии; не исходим из того, что большой список обязательно бесплатен.

## 4. Порядок реализации

| Этап | Работа | Результат и критерий завершения |
|---|---|---|
| 0. Установить исходное поведение | Проверить версию установленной сборки, только маршрутные директивы профиля и правила от адаптера; воспроизвести MAX и проблемные сервисы с VPN и без него | Понятно, есть ли существующее исключение MAX, откуда оно берётся и какие сценарии действительно ломаются |
| 1. Проверить подход на iPhone | Собрать минимальный каталог для всех трёх групп; техническим прототипом проверить маршруты, IPv6, DNS и режимы enforceRoutes | Адреса и их происхождение записаны; обязательные сценарии идут напрямую, контрольный трафик — через VPN; широких неподтверждённых исключений нет |
| 2. Реализовать модель и каталог | Общие типы, ресурс, валидация, версия схемы, объединение маршрутов, тесты | Плохие данные не расширяют исключения; старый профиль ведёт себя как раньше |
| 3. Интегрировать расширение | Применение в provider, повторное применение при reconnect, ошибки и минимальная диагностика | Сохраняются endpoint, DNS, IPv6-защита и маршруты адаптера; нет накопления правил |
| 4. Добавить сохранение и интерфейс | Экран «Без VPN», сводка, сохранение только при отключении, сохранение выбора при смене ключа, ru/en | Видимый выбор соответствует профилю; ошибки и занятость понятны; нет гонки с подключением |
| 5. Провести приёмку и подготовить выпуск | Автотесты, сборки, матрица iPhone, описание поведения и обновление политики | Проверяемые сценарии пройдены, ограничения записаны; функция готова к отдельному решению о выпуске |

Этапы выполняем последовательно: прототип определяет пригодность данных и режим маршрутизации; затем общий контракт определяет код расширения и приложения. План не требует параллельных агентов или отдельных чатов.

**Условие перехода после этапа 1.** Если надёжные узкие IP-диапазоны не покрывают обязательные сценарии либо приложение отклоняет соединение даже при доказанном прямом маршруте, не объявлять задачу решённой. Зафиксировать конкретную зависимость/причину и пересмотреть план. Если проблема именно в динамических доменах и общих CDN, исследовать доменную маршрутизацию с DNS-aware proxy/tun2socks как отдельное расширение архитектуры. Такой механизм не закладываем скрыто внутрь текущего мостика OpenVPN.

Для тестирования последовательности сохранения выделить маленькую обёртку над чтением/записью VPN-профиля; не пытаться тестировать всю SwiftUI-сцену через моки. В `Package.swift` явно подключить зависимости общего кода и ресурсы. Каталог тестируется офлайн по проверенной версии, а не по текущему публичному DNS.

Команды при реализации: `make test`, `make strings-check`, `make build`, `make release-check`, `git diff --check`. В этой рабочей копии фреймворк не присутствует; перед сборкой нужен существующий проверенный артефакт с provenance либо `make framework`. Не заменять его известным дефектным готовым бинарником.

### 5.2. Проверки на физическом iPhone

Использовать российский Wi-Fi и мобильную сеть. Матрица: IPv4, dual stack и по возможности IPv6-only/NAT64; текущая iOS и минимальная реально поддерживаемая тестовая версия. Результаты привязывать к сборке, версии каталога, сети и версии приложения сервиса.

| Сервис | Обязательный сценарий |
|---|---|
| Ozon в Safari и приложении | Открыть каталог, поиск, карточку и изображения; войти в свой аккаунт; открыть корзину и экран оформления без оплаты |
| Wildberries в Safari и приложении | Каталог, поиск, изображения, вход, корзина, выбор пункта выдачи без заказа |
| Яндекс | Поиск; вход через Яндекс ID; Карты и построение маршрута; открытие Почты; загрузка/скачивание тестового файла Диска |
| Яндекс Go | Холодный запуск, вход, карта, геолокация, выбор адреса, расчёт стоимости без заказа поездки |
| MAX | Существующий доступ и установленный маршрут не ухудшились; отправка сообщений или звонки только в отдельно согласованном тесте |
| Контрольный ресурс вне списка | При VPN включённом запрос по-прежнему приходит с IP VPN; при выключенных новых исключениях поведение совпадает с исходной сборкой |

Повторить с каждой группой отдельно и со всеми вместе. Проверить открытые до подключения приложения, повторный запуск, Wi-Fi ↔ LTE в обе стороны, сон/пробуждение, перезапуск приложения-клиента, переподключение и старт из Настроек iOS без открытого OVoC Client.

**Доказываем маршрут отдельно от работоспособности.** Для тестового endpoint под нашим контролем сравнить адрес источника с VPN и без него при узком временном исключении. Для настоящих сервисов дополнительно подтвердить назначения и выход через физический интерфейс с помощью локальной диагностики/RVI или тестового роутера; сопоставить с наблюдением туннеля. Один открывшийся экран или счётчики `PacketFlowBridge` недостаточны: прямой трафик не проходит через этот мост. Не делать TLS MITM и не сохранять пользовательские payload. Временный тестовый endpoint и правила не включать в production-каталог.

Системный DNS должен сохранять прежний маршрут. Ответ DNS через зарубежный VPN может отличаться от ответа российской сети и выбирать другой узел CDN: покрытие проверяем именно с DNS подключённого VPN, а не только по локальному `nslookup`. Встроенный DoH/DoQ приложения маршрутизируется по IP как другой трафик; поддержку произвольного внешнего DNS-профиля или Private Relay не обещаем без отдельной проверки. При NAT64 нельзя исключать весь `64:ff9b::/96` или иной префикс трансляции. Если текущий VPN или новая функция не работают в такой сети, точно записать ограничение; поддержку мобильных сетей без оговорок не заявлять.

Различать «сервис открылся», «подтверждён прямой маршрут» и «все сценарии пройдены». Результат теста одной главной страницы не означает поддержку сервиса целиком. Авторизация выполняется владельцем аккаунта; покупки, оплата и реальные поездки не нужны для этой приёмки.

## 6. Ошибки и поведение при отказах

| Отказ | Поведение | Как проверяем |
|---|---|---|
| Каталог/политика повреждены при непустом выборе | Не поднимать VPN с неизвестными исключениями; объяснить ошибку и возможность отключить группы | Unit + тест старта |
| Нет подходящего CIDR для новой зависимости | Зависимость остаётся под прежней политикой VPN; совместимость сервиса не считается подтверждённой | Приёмка сервисов; исправление каталога через выпуск |
| Новый диапазон захватывает DNS VPN | Отказ с отдельной ошибкой, без глобального обхода DNS | Unit + профиль с DNS внутри сети Яндекса |
| Применение настроек iOS завершилось ошибкой | Пробросить ошибку в существующую обработку; не подтверждать успешную конфигурацию | Инъекция ошибки/задержки |
| Сеть изменилась при reconnect | Сохранить прежние маршруты на промежуточном nil; собрать правила заново для новых настроек | Unit + Wi-Fi/LTE |
| Сохранение профиля не удалось | Перечитать фактическую настройку, показать ошибку; не оставлять ложный переключатель | Тест хранилища |
| Приложение сервиса определяет сам факт активного VPN | Не пытаться скрывать системный статус; подтвердить причину и явно ограничить обещание | Сравнение с VPN off и доказанным прямым маршрутом |
| Требуется слишком много маршрутов или слишком широкие сети | Не обрезать список и не расширять охват автоматически; не проходить этап 1/приёмку | Валидация и измерения |

## 7. Что не входит в первую версию

- Произвольный редактор доменов и CIDR: требует отдельного UX, проверки пользовательских правил и поддержки ошибок.
- Исключение приложений по bundle ID: не соответствует возможностям обычного consumer-профиля iOS.
- Автоматические списки «вся Россия», банки и госуслуги: это другой охват и другие последствия для маршрутизации.
- Автоопределение страны, удалённый updater, сервер подписанных списков: для первого проверяемого каталога не нужны.
- DNS-перехват, анализ TLS/SNI, tun2socks и новое VPN-ядро: только если эксперимент докажет непригодность более простого подхода.
- Изменение VPN-сервера, смена протокола, новый kill switch и скрытие признаков активного VPN от сторонних приложений.
- Переключение маршрутов во время активной сессии: исключает отдельную сложность с уже открытыми сокетами и синхронизацией состояния.
- Гарантия работы любого будущего сервиса Яндекса и любой версии стороннего приложения без обновлений каталога.

### Исправление сборки 7

Пользователь подтвердил сценарий: выбор групп → «Закрыть»/свайп → подключение.
В сборке 4 переключатели меняли только `@State`; запись выполнялась отдельной кнопкой
«Сохранить» ниже пояснений. Закрытие уничтожало черновик, а подключение корректно читало
прежний профиль без новых исключений. Сборка 7 заменяет этот сценарий автосохранением
через `ServiceBypassSelectionModel` и прежнюю проверенную транзакцию профиля.

Три новых теста проверяют сохранение всех групп до закрытия и последующего чтения,
блокировку при задержке записи и игнорирование промежуточных событий профиля,
восстановление после ошибки и успешную повторную попытку. Из опубликованной сборки 6
сохранены исправления запуска и восстановления VPN. 129 строк ru/en согласованы с кодом.

Отдельный агент выполнил независимое ревью изменений от `647cd2e`, исправления выбора
и опубликованной логики переподключения сборок 5/6. Подтвердил исходный дефект интерфейса
и нашёл P2: отсутствие подходящего DNS для пробы ошибочно считалось провалом туннеля.
Для этого случая добавлен режим `unverified`: отменяется дедлайн пробы, остаётся наблюдение
за путём и адаптером, успешность подтверждается свежими входящими пакетами. Каждая новая
физическая сеть получает отдельный бюджет, повторы на том же пути остаются ограниченными.
Пять отдельных регрессий проверяют запуск, бюджет восстановления, сетевые события и остановку.
Физическое тестирование UI и сетевой совместимости этим ревью не заменяется.
