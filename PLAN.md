# iOS-клиент для личного VPN (AmneziaVPN · OpenVPN over Cloak)

> План написан для новичка в iOS-разработке. Технические термины и команды — на английском (так они выглядят в коде и документации), объяснения — по-русски. Реализовывать будет Claude Code по шагам; тебе останется несколько действий, которые невозможно сделать из командной строки (оплатить аккаунт, залогиниться в Xcode, воткнуть iPhone в кабель, нажать пару кнопок на телефоне).

## Контекст

**Что делаем.** Нативное iOS-приложение — минимальный VPN-клиент к твоему собственному серверу AmneziaVPN, который поднят с протоколом **OpenVPN over Cloak**. Cloak маскирует VPN-трафик под обычный HTTPS, поэтому такое соединение сложно заблокировать.

**Зачем своё приложение, а не официальное.** Официальное приложение AmneziaVPN удалили из российского App Store (в 2025 Apple по требованию Роскомнадзора убрала больше 1200 приложений). Своё приложение мы раздадим напрямую через TestFlight — этот канал пока не трогают, и сама Amnezia сейчас раздаётся именно так.

**Итог, к которому идём.** Приложение с одной кнопкой «Подключить», которое ты ставишь себе и 3–5 родственникам. Ключ подключения (`vpn://…`, тот же, что экспортирует Amnezia) либо вшит в сборку, либо вставляется копипастом. Публикация в App Store — возможно позже, но там есть серьёзные препятствия (см. последний раздел), поэтому это **не цель версии 1**.

**Ключевой вывод исследования.** Не нужно писать VPN «с нуля» и не нужно форкать огромное приложение Amnezia (оно на Qt, для новичка это тупик). Amnezia — open-source, и вся сложная часть (OpenVPN + Cloak) уже собрана в переиспользуемый бинарный компонент `OpenVPNAdapter.framework`. Наша задача — **несколько сотен строк Swift** поверх готового фреймворка. Живой форк библиотеки поддерживается Amnezia (последний коммит — март 2026).

## Как это работает (модель для новичка)

Три понятия, без которых дальше не разобраться:

1. **Network Extension (NE) — «packet tunnel provider».** iOS не даёт обычному приложению перехватывать сетевой трафик. Для VPN нужен специальный мини-процесс — расширение (`NEPacketTunnelProvider`), который система запускает отдельно от приложения. Приложение — это только кнопка и настройки; всю работу VPN делает расширение. **Важное ограничение: у расширения жёсткий лимит памяти ~50 МБ**, и оно **не работает в симуляторе** — тестировать можно только на настоящем iPhone.

2. **OpenVPN + Cloak — как они соединены.** На десктопе Cloak — отдельная программа-прокси. Но на iOS (из-за лимитов и запрета запускать вложенные процессы) Amnezia сделала иначе: Cloak скомпилирован на языке Go в статическую библиотеку и **вшит прямо внутрь движка OpenVPN** как «транспорт». То есть OpenVPN не открывает TCP-сокет на `127.0.0.1`, а вызывает функции Cloak напрямую в памяти. Для нас это плюс: со стороны Swift всё выглядит как обычный OpenVPN, а «магия Cloak» включается **одной строчкой** (`setPTCloak`) плюс блоком `<cloak>…</cloak>`, дописанным в конфиг.

3. **Ключ `vpn://…`.** Когда в Amnezia жмёшь «Поделиться» — получается строка `vpn://<длинный-base64>`. Внутри: сжатый zlib JSON, где лежит полный текст `.ovpn`-профиля (с сертификатами) и настройки Cloak (UID, публичный ключ сервера, домен-маскировка и т.д.). Наше приложение умеет эту строку распаковать и превратить в готовый конфиг. Это позволяет тебе просто прислать родственнику ключ, а не настраивать каждому вручную.

**Поток данных в итоге:** трафик телефона → наше расширение → OpenVPN-движок → Cloak (маскирует под HTTPS) → твой сервер.

**Одна тонкость, из-за которой всё может «не поехать» (мы её закрываем заране).** Поскольку OpenVPN внутри думает, что соединяется с `127.0.0.1`, iOS не понимает, какой у реального сервера IP, и может завернуть трафик самого Cloak обратно в туннель — получится петля, и интернет пропадёт. Решение: явно исключить IP сервера из маршрутов туннеля (двумя способами сразу — строкой `route <IP> 255.255.255.255 net_gateway` в профиле и добавлением в `excludedRoutes` в коде). Это отдельно проверяется на этапе M3.

## M0 — Apple Developer аккаунт (сделать в первую очередь, идёт параллельно с кодом)

Это единственный настоящий блокер. Регистрация занимает время (одобрение Apple 1–2 дня, иногда дольше из-за проверки), поэтому запускаем сразу, а Claude Code параллельно пишет скелет приложения (M1 частично можно начать без аккаунта).

### Оплата из России (актуально на август 2026 — важно)

Ситуация ужесточилась, поэтому по порядку:
- **Российские карты — не работают** (с 2022). **Оплата через баланс МТС — тоже больше не работает** (её отключили в апреле 2026, тогда же Apple остановила обработку платежей в РФ).
- **Что работает:** зарубежная карта, реально принимаемая Apple. На практике люди используют:
  - карту банка Казахстана / Грузии / Армении / другой страны;
  - зарубежные виртуальные карты (Wise, Revolut, Payoneer и т.п.);
  - карту родственника/друга за границей.
- **Apple Gift Card и баланс Apple ID для оплаты Developer Program НЕ подходят** — только карта.
- Регистрируешься как **Individual** (физлицо). Этого достаточно для TestFlight, включая публичную ссылку для родственников. (Тип «Organization» нужен только для публикации VPN в App Store — это отдельная история, см. конец.)
- При регистрации Apple прогоняет проверку на санкционные списки — иногда одобрение подвисает на дни/недели. Это нормально, просто закладываем время.

### Шаги
1. Зарегистрироваться: https://developer.apple.com/programs/enroll/ — Apple ID, тип **Individual**, оплата $99 зарубежной картой.
2. После одобрения: **один раз** зайти в Xcode → Settings → Accounts, добавить свой Apple ID (это даст `xcodebuild` право автоматически выпускать сертификаты и профили — портал в браузере кликать не придётся).
3. Позже (нужно только для M6, но сделать можно сразу): в App Store Connect → Users and Access → Integrations создать **App Store Connect API key** (роль App Manager), скачать файл `.p8`, положить в `~/.private_keys/`. Через него сборки будут загружаться в TestFlight одной командой.
4. Сказать Claude Code свой **Team ID** (10-символьный код, виден в developer.apple.com → Membership) — он подставит его в проект.

**Проверка (что ты видишь):** письмо-подтверждение от Apple; в Xcode → Accounts виден твой Team; команда `xcodebuild -showBuildSettings | grep DEVELOPMENT_TEAM` печатает твой Team ID.

Кодовое имя проекта — **PersonalVPN** (можно переименовать). Bundle ID: приложение `com.razhev.personalvpn`, расширение `com.razhev.personalvpn.tunnel`, App Group `group.com.razhev.personalvpn`.

**Почему `ConfigKit` вынесен в отдельный пакет.** Приложение собирается только под устройство (у фреймворка нет «симуляторной» версии). Но логику разбора ключа очень хочется тестировать быстро, без телефона и подписей. Отдельный пакет, который работает и на macOS, даёт команду `swift test` прямо на Mac — мгновенная проверка. Это самое важное решение для удобства новичка: вся хрупкая логика (распаковка, разбор JSON, сборка профиля) покрыта тестами и не требует ни телефона, ни аккаунта.

**Разделение труда приложение/расширение.** Всю распаковку и сборку конфига делает **приложение** в момент импорта. Расширению оно отдаёт уже готовый текст `.ovpn` (с уже дописанным `<cloak>`) плюс IP сервера — через словарь `providerConfiguration`. Расширение ничего не парсит: так меньше кода и меньше расход памяти (важно из-за лимита 50 МБ).

## Милестоны (этапы) с проверками

Каждый этап заканчивается конкретным «ты видишь X на телефоне». Порядок выбран так, чтобы **сначала снять самые большие риски**. «Сессия» ≈ один заход работы на 2–3 часа.

### M1 — Скелет приложения + расширения с «пустышкой»-туннелем (1–2 сессии)
Собираем оба таргета, кнопку, менеджер туннеля — **без VPN-логики**. Расширение поднимает фиктивный туннель (фейковый IP, узкий маршрут `10.8.0.0/24`, НЕ весь трафик — иначе телефон останется без интернета).

Цель: убедиться, что подписи, entitlements, App Group и профили работают, **до** появления любой сложности с VPN.

**Проверка:** первое нажатие «Подключить» → системное окно «PersonalVPN хочет добавить конфигурацию VPN» → Allow → **появляется значок VPN** (на iPhone с Face ID — в Пункте управления; в Настройки → VPN профиль «Подключено»), статус «Подключено»; выключение убирает его; обычный интернет продолжает работать; в LogView видны строки, записанные расширением (это доказывает, что App Group работает).

### M2 — Получение фреймворка и проверка символов (1 сессия; +1–2 если понадобится запасной путь)
Скрипт скачивает готовый `OpenVPNAdapter.framework` из релизов Amnezia (`3rd-build-ga`, релиз v1.0.42). Скрипт `verify-framework.sh` — **это ворота качества, гоняем до того, как что-то подключать**:
- `lipo -info` → только arm64 (устройство);
- `nm` находит символы `Cloak_dial` и `Initialize_cloak_c_client` (значит Cloak реально внутри; если их нет — берём фреймворк из репозитория `3rd-prebuilt`, а в крайнем случае собираем из исходников);
- в заголовках есть `setPTCloak` — **записываем точное имя метода в README**, потому что весь M3 на него завязан.

Подключаем фреймворк, пересобираем, в расширении создаём объект `OpenVPNAdapter()` и логируем — это доказывает, что фреймворк реально грузится в процессе расширения (ошибки встраивания вылезут здесь, а не в M3).

**Проверка:** `verify-framework.sh` печатает три PASS; пустышка-туннель по-прежнему подключается; в логах «OpenVPNAdapter loaded».

### M3 — Настоящее соединение на «зашитом» конфиге (2–4 сессии; главный риск-этап)
Ты один раз экспортируешь `vpn://`-ключ из рабочей Amnezia. Скрипт `decode-vpnkey.py` на Mac распаковывает его в читаемый вид. Claude вручную сверяет данные и кладёт готовый конфиг в приложение (только для DEBUG-сборки — импортёр ещё не нужен). Пишем полноценный `PacketTunnelProvider` (детали ниже).

**Тестируем БЕЗ подключённого отладчика Xcode** (известный баг Go на iOS: под отладчиком код Cloak работает со скоростью ~5 кадров/сек и кажется «зависшим»; ставим только через CLI).

**Проверка:** «Подключить» → статус «Подключение» несколько секунд (это рукопожатие Cloak) → «Подключено»; открываешь сайт-определитель IP → показывает **IP твоего сервера**; сайты грузятся (значит петли маршрутов нет и DNS идёт через туннель); оставляешь на 10 минут — держится (в логах видно потребление памяти, комфортно ниже 50 МБ); отключение чистое; переподключение работает.

Если на iOS 26 будет «Подключено, но трафика нет» — это известная проблема Amnezia (#2072); лечится пересборкой фреймворка из исходников (скрипт готов, в нём мартовские правки 2026).

### M4 — Импорт ключа `vpn://` + тесты + вшитый ключ по умолчанию (2–3 сессии)
Пишем весь `ConfigKit` и юнит-тесты (синтетический ключ собирается прямо в тесте: JSON → zlib → префикс длины → base64url → `vpn://`). Тесты покрывают: успешную распаковку и запасной путь; DNS-подстановку (когда плейсхолдеры есть и когда нет); вставку `route`; правила типов (`"StreamTimeout":"300"` → число, `UID` остаётся строкой — именно на этом легко ошибиться); имя-хост вместо IP; мусор на входе → понятная ошибка. Экран вставки ключа; авто-импорт вшитого `default.vpnkey`.

**Проверка:** `cd ConfigKit && swift test` — всё зелёное на Mac; затем на телефоне: удаляешь приложение, ставишь заново, вставляешь настоящий ключ, «Подключить» → IP сервера. То есть импортёр воспроизводит результат M3 без ручной подготовки.

### M5 — Доводка (1–2 сессии)
Понятный статус для всех состояний; показ ошибки под кнопкой (через `fetchLastDisconnectError` + файл `last_error.txt`); кнопка «Поделиться логами»; локализация ru/en; иконка; опционально авто-подключение (по умолчанию **выключено**, с предупреждением, что при мёртвом сервере iOS будет назойливо переподключаться).

**Проверка:** телефон на русском — интерфейс на русском; выключаешь сервер → под кнопкой появляется читаемая ошибка, а не молчаливое «Отключено»; логи экспортируются.

### M6 — Раздача через TestFlight (1–2 сессии + 1–2 дня на ревью)
В App Store Connect создаём запись приложения. Скрипт `upload-testflight.sh` собирает архив и заливает его (через API-ключ из M0). Экспорт-комплаенс по шифрованию закрывается флагом `ITSAppUsesNonExemptEncryption=false` (стандартная TLS/AES-криптография — освобождена).

Раздача: **внешняя группа тестеров + публичная ссылка** (лучший вариант для семьи: поставить приложение TestFlight → нажать ссылку). Первую сборку каждой версии проверяет Beta App Review — VPN-утилиты проходят; в заметках для ревью пишем, что это личный клиент к собственному серверу, прикладываем рабочий тестовый ключ. Запасной вариант, если ревью буксует: внутренние тестеры (до 100 человек, вообще без ревью, но нужно добавить их Apple ID в команду).

В репозитории оставляем: текст заметок для ревью, шаблон сообщения родственникам на русском, и памятку «перезаливать сборку каждые ≤90 дней» (у TestFlight-сборок срок годности 90 дней).

**Проверка:** сборка в статусе «Ready to Test»; твой телефон ставит её по публичной ссылке; один родственник подключается и видит IP сервера.

**Итого ≈ 8–14 сессий за 2–4 недели** (в основном время съедают неопределённость M3 и две паузы на стороне Apple: одобрение аккаунта и ревью).

## Ключевые технические детали

### `PacketTunnelProvider` (ядро расширения)
- **startTunnel:** читает из `providerConfiguration` готовый текст `.ovpn`, IP сервера и DNS → строит `OpenVPNConfiguration` (`fileContent`, `tunPersist = true`, вызов `setPTCloak`) → `adapter.apply(...)` (ошибки разбора конфига логируем дословно — это самый вероятный класс багов) → запускает «сторожевой таймер» на 30 сек (рукопожатие Cloak идёт несколько секунд; если не уложились — понятная ошибка вместо тихого убийства системой) → `adapter.connect(using: packetFlow)`. Пароль/логин не нужны — сертификаты уже внутри профиля.
- **Делегат `configureTunnelWithNetworkSettings`** (тут закрываем петлю и настраиваем DNS): `matchDomains = [""]` (весь DNS в туннель); если адаптер не отдал DNS — берём из строк `dhcp-option DNS` в конфиге или из `dns1/dns2`; **добавляем IP сервера в `excludedRoutes` как /32** (страховка поверх строки `net_gateway` в профиле).
- **handleEvent/handleError:** `.connected` → снять таймер, завершить старт успешно; фатальная ошибка (`OpenVPNAdapterErrorFatalKey`) → записать в `last_error.txt` и завершить с ошибкой.
- **stopTunnel:** `adapter.disconnect()`, с 5-секундным подстраховочным таймером.
- **sleep/wake:** в v1 простой проброс; `tunPersist=true` держит туннель при внутренних переподключениях адаптера.

### Логирование (отладка без отладчика)
Поскольку отладчик Xcode ломает Go-код, а расширение не может печатать в консоль, единственный практичный канал — файловый лог:
- `RingLogger` пишет в `<AppGroup>/tunnel.log` (с ограничением размера), дублирует в `os.Logger`, раз в 30 сек пишет строку с текущим потреблением памяти (так видно приближение к лимиту 50 МБ).
- В приложении экран LogView показывает этот файл и даёт «Поделиться» — так родня пришлёт тебе диагностику.
- На Mac по кабелю: Console.app с фильтром по subsystem, либо `log collect --device-name "<iPhone>" --last 10m`. Команды — в README.

## Раздача родственникам (итоговый пользовательский путь)

1. Ты собираешь семейную сборку с **вшитым ключом** (`default.vpnkey`) и заливаешь в TestFlight (`make upload`).
2. Присылаешь родственнику: (а) ссылку установить **TestFlight** из App Store, (б) публичную ссылку-приглашение на приложение.
3. Родственник: ставит TestFlight → жмёт ссылку → открывает приложение → одно нажатие «Подключить» (ключ уже внутри, настраивать ничего не надо).
4. Раз в ≤90 дней ты перезаливаешь сборку (TestFlight сам обновит её у всех). Поставим напоминание.

Всё это работает на российских Apple ID — проверено на примере самой Amnezia.

## На будущее: App Store (коротко, это НЕ цель v1)

Три препятствия, которые надо трезво понимать:
1. **Правило 5.4 Apple:** VPN-приложения могут публиковать только аккаунты типа **Organization**, не физлица. Понадобится юрлицо и D-U-N-S номер.
2. **Лицензия AGPL-3.0** у OpenVPNAdapter/OpenVPN3 конфликтует с условиями App Store (для личной раздачи через TestFlight обязательств не возникает, а вот публикация — уже распространение).
3. **Российский App Store** систематически вычищает VPN по требованию Роскомнадзора — листинг там самый хрупкий канал.

Вывод: TestFlight — правильный и достаточный канал для твоей задачи. К App Store возвращаемся, только если 90-дневный цикл перезаливки станет невыносимым.

## Как проверяется результат (end-to-end)

- **На Mac, без телефона:** `cd ConfigKit && swift test` — вся логика разбора ключа зелёная.
- **Ворота фреймворка:** `./scripts/verify-framework.sh` — три PASS (arm64, символы Cloak, `setPTCloak`).
- **На твоём iPhone (главная проверка):** установить (`make install`), «Подключить» → значок VPN → сайт-определитель показывает **IP сервера** → сайты открываются → 10 минут стабильно → чистое отключение.
- **Раздача:** сборка в TestFlight «Ready to Test» → устанавливается по публичной ссылке → один родственник успешно подключается.

## Открытые технические вопросы (уточняются в коде, не блокируют старт)
- Точное имя/сигнатура `setPTCloak` и тип completion в делегате — фиксируются в M2 из заголовков фреймворка (форк менял API в марте 2026).
- Твой Team ID — подставляется в `project.yml` после M0.
- Версия iOS на твоём **рабочем** iPhone: если это iOS 16, установка по кабелю чуть сложнее (нужен `ios-deploy` вместо `devicectl`, который требует iOS 17+). На раздачу родне не влияет.
